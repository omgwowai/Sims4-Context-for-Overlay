# Autonomy 采集方案

2026-09-16。经 grill-me 访谈确认采集边界。本文保留研究结论与实施设计；已按此接入 0.7.0 运行时代码，完成离线核验，尚未实机验收。具体已实现范围、缺失字段及配置见[使用说明](autonomy-capture.md)和[验证报告](validation/2026-09-16-autonomy-implementation.md)。

## 已确认的边界

| 事项 | 用户已确认的选择 |
|---|---|
| 生效门槛 | 成功进入队列。入队后未开始就取消，也保留其决策。继续关联开始、取消、失败与完成。 |
| 候选数量 | N 初始为 5。实际选中项必须保留，其余位置取权重最高的 4 项；不额外扩到 6 项。 |
| 行为层级 | 主行为＋内部真实决策。延续执行的步骤不另造决策，技术条目分层展示。 |
| 多层选择的 N 限制 | 每个选择层级分别最多 5 项；整次决策可以包含多张候选表。各层权重与概率独立解释。 |
| 筛选淘汰信息 | 只保留原因计数，不保存被条件检查淘汰候选的逐条明细。计数范围是最终成功提交决策中实际观测到的检查。 |
| 评分深度 | 每层所有保留候选都记录游戏实际提供的评分组成；缺失项明确标记。 |
| 随机数细节 | 保存权重、原概率、实际选中项及多任务检查；本次不额外追踪底层抽签数值。 |
| 立即型交互 | 包含。确认已经进入立即执行即保留，成功或失败另外记录。 |

## 三部分分别如何采集

| 部分 | 建议采集内容 | 来源与边界 |
|---|---|---|
| 候选筛选 | 本次实际评估、评分及进入抽签的数量；被淘汰的阶段与原因计数；保留候选的可用性结果。 | 读取实际请求、GSI `Affordances` / `Objects` 及实际执行的测试回调。只描述引擎本次确实评估过的范围；不重新执行测试，不把未枚举等同于禁止。失败候选没有可比较的最终权重，不强行放进 Top N，也不另存失败候选明细。 |
| 评分 | 保留候选的原始评分、最终抽签权重、原始排名，以及游戏已提供的需求贡献、关系与 Buff 倍率、路径时间、机会成本等明细。 | 优先读取实际 `InteractionScore`、`ScoredInteractionData` 与 GSI，保留来源和缺失字段。评分和路程换算后的选择权重分开；不根据事后需求值反推评分，也不重新调用评分器。 |
| 随机选择 | 选择方式、实际抽签池数量、总权重、保留候选的原概率、实际选中对象／索引、遗漏项概率总量；另存多任务检查的实际随机值、阈值、是否适用及通过结果。 | 在实际选择调用中取输入与返回结果，结合 GSI `Probability`。各层概率是对应层的条件概率，不能跨层排名或直接混成一个池。截取明细后不重新归一化。本次不追踪行为抽签的底层随机数，也不额外调用随机函数或多任务 getter 来补数据。 |

N 限制只影响写出的候选明细，不改变游戏考虑的候选数、评分、排序、抽签或队列行为。

候选数量不足 N 时保存实际存在的条目。实际选中项保留其原始排名，不因强制保留而改成第 1 名。并列权重以原候选顺序稳定展示，并保留并列信息。概率分母来自各层完整的实际选择池；只展示 N 项时，另外保存未展示项的总概率。确定性最高分选择和均匀选择分别标明，不把所有评分模式都解释为“分数越高，概率越大”。

评分组成读取游戏已经实际生成的结构化值；例如 `commodity_scores`、`rel_utility_score`、`buff_utility_score`、`route_time`、`opportunity_costs`。这些值可能是贡献项、倍率或成本，不能统一换算成相加为 100% 的“原因占比”。存在 GSI 明细过期或无法唯一关联候选的情况时，保留原总分与覆盖标记，不重新计算一个解释分数替换它。

## 记录生命周期

1. 一次真实选择发生时，分配采集侧请求／选择序号，提取稳定值到有上限的临时缓冲区。记录选择时刻、Sim、模式、选择层级、候选与选中交互实例。
2. 将结果绑定到具体交互；普通交互等待执行系统确认成功入队，立即型交互等待确认已经进入执行，再把决策写入正式历史。未选中、未提交，以及未达到上述任一门槛的请求不写成行为决策，可保留汇总诊断计数。
3. 入队后的开始、取消、失败、完成沿用现有交互生命周期；不得把入队成功解释为执行成功。
4. 自主子行为可能提前选择并缓存。缓存命中时关联原选择记录，分别保留选择时刻和入队时刻；不虚构一次新评分。缓存失效的未提交记录释放。
5. 使用具体请求／选择序号与交互实例 ID，避免用“这个 Sim 最近一次决策”推断因果。父子交互只在有明确来源链时继承关联，不把一个动作的后续步骤计算成新决策。
6. 区域切换、对象失效、缓冲区超限时保留覆盖与丢弃计数，释放暂存。没有决策证据时保留已有交互事件，并明确标记决策缺失。

这里的“一轮”需要用采集侧唯一 ID 表达，不能只拿 Python 请求对象的地址充当持久 ID。同一个 `AutonomyRequest` 可复用来预选多个缓存子行为；每次实际选择应有独立序号，属于同一选择链的层级再建立父子关系。只在最终行为达到保留门槛时提交相应选择链。

实施时沿用当前项目的活动地块、已实例化实体范围；保留原始请求模式、`context.source` 和 `is_script_request` 等来源证据。某段脚本也可能调用 Autonomy 选择器，因此不能把所有进入该算法的请求都解释为“人物完全自发的意图”。

建议的数据结构分为四部分：

| 结构 | 主要内容 |
|---|---|
| 决策记录 | 决策 ID、执行者、模式与来源、选择时刻、提交／入队时刻、是否来自缓存、最终交互引用。 |
| 各层选择 | 层级 ID、父层级、选择方式、实际池大小和总权重、选中项、每层最多 N 个候选、未展示概率、覆盖状态。 |
| 候选明细 | 稳定候选标识、行为与目标引用、原排名／顺序、总分、最终权重、原概率、实际评分组成、各字段来源。 |
| 筛选与执行关联 | 按实际观测阶段／原因汇总的淘汰记录数，及现有交互的排队、开始、取消、失败、完成记录。 |

以 `autonomy.decision` 作为事件记录模块的新类别即可复用现有历史、持久化与语义化流程；无需建立另一个互不关联的日志系统。候选里的落选者／对象属于比较证据，不能被当作该行为实际发生的参与者。最终接口及显示布局在实现阶段依据现有契约核对。

技术细节仍需实现验证：`on_added_to_queue` 发生后，队列整理还可能让提交最终返回失败。因此普通交互的保留门槛需要核对完整的提交返回值，不能只凭该通知。立即型交互绕过队列，以实际进入执行的证据作为门槛；后续执行失败不能反过来删除已经记录的决策。

只保存成功入队的决策，可以降低磁盘和历史数据量，但为了取得入队前的候选，仍需在选择发生时暂存。不能承诺它消除所有采集开销；需要实机测量 GSI 评分明细生成成本和缓冲峰值。

## 对参考实现的核对

参考 [Experience decision_hook](C:/sources/Sims4-Experience-Mod/src/experience_recorder/hooks/decision_hook.py:1) 的 GSI 转写入口，不能原样移植其关联与筛选规则。

| 发现 | 对本方案的影响 |
|---|---|
| `_candidates` 使用 `list(table)[:TOP_K]`，没有排序。 | 本机游戏的概率表按分数升序生成。普通路径引擎自身已裁到 5 项，截前 5 项可能恰好完整；`consider_all_options=True` 时会截到低分项。必须按真实阶段内的最终权重排序后选取。 |
| 同一次归档的概率表可以拼接两轮选择，第二轮带 `interaction_prefix='**'`。 | 不能截整个表的前 5 项，也不能把不同选择层级的概率混为一体。 |
| 原实现读取 `multitasking_roll`，本机游戏概率条目的字段为 `multitask_roll`。 | 此字段会读不到；更重要的是，它是多任务门槛的随机值，并非行为抽签的底层随机值。 |
| 有 `gsi_data` 就写 `autonomy_choice`。 | 概率表存在时仍可能被多任务检查拦下；有数据不能证明选中结果已提交或已生效。 |
| `LAST_DECISION[sim_id]` 用于后续交互的父关联。 | 同一人物的并行交互和缓存子行为可能错连。必须使用具体交互和请求／选择实例的证据。 |
| 关闭随机化时，GSI 概率表可能只含最终赢家。 | 不能把这一行解释为本轮只考虑过一个行为。候选比较还需从实际评分输入读取，并区分“有评分”与“有选择概率”。 |

## 后续验收应覆盖

- 普通交互未选中或未成功提交的请求不写正式决策；提交成功但之后取消／失败的请求保留。立即型交互进入执行后保留，即使其最终执行结果为失败。
- 选中项在前 N 内与前 N 外时均正确保留，明细不超过确认的 N 限制。
- 权重排名与游戏实际选择池一致，原概率和剩余概率正确，确定性选择不伪装成随机抽签。
- 多层选择、同一请求对象复用、缓存子行为、并行交互、父子衔接不会错连。
- 源码与已安装版本差异、GSI 未生成数据、缓冲超限均显式报告覆盖，不补造数据。
- 开关前后的游戏行为、随机调用次数与返回结果不变；实测开销及单局数据量。
