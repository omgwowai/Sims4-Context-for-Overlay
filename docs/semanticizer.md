# 数据语义化模块

版本：v0.2。日期：2026-09-14。状态：首版确定性转换已实现，通过离线检查及真实游戏数据的中文表达核验。入口见[运行说明](runtime-usage.md)，实际结果见[验证记录](validation/2026-09-14-first-round.md)。

## 1. 职责与独立性

接收项目约定格式的快照或事件数据，使用版本化资源、规则与模板生成规范含义和可读文本，保留事实身份、原始值及证据。总体边界见[三模块设计](modular-context-provider.md)。

核心转换可以在游戏外使用普通数据和规则资源运行，不导入游戏服务或隐式启动采集。游戏内的名称或资源解析通过明确的适配输入提供；缺失时按规则回退。事件记录和 Context 采集器均可调用这一能力。

首轮中文输出采用逐项、逐条解释：状态、主要交互和展开后的内部观测均可对应到原始数据。输出时间、参与者、目标、触发来源和已有结果证据，不生成活动汇总、主观动机或叙事回顾。连续采样仅解释区间差异，未经证明不表达行为因果。

## 2. 三个组成部分

| 部分 | 作用 | 示例 |
| --- | --- | --- |
| 名称目录 | 将资源/定义身份对应到名称、类别及含义 | 某个交互定义对应“练习国际象棋” |
| 语义规则 | 依据字段和来源确定角色、阶段、结果、数值及单位 | 排队、运行和终态分别表达 |
| 文本模板 | 将已规范化的事实表达为指定语言 | “A 的练习国际象棋交互被取消” |

标签字典只能解释定义，不能证明某次行为发生或完成。第一版采用少量精确规则、有限条件与模板；规则数据不执行任意 Python 或模型生成的代码。

## 3. 事实与措辞

以下是规则设计示例，不是本项目已经采集到的事实：

| 有依据的输入 | 允许的表达 |
| --- | --- |
| 只有交互定义 | “练习国际象棋” |
| 已确认排队、尚未开始 | “A 已排队等待练习国际象棋” |
| 已确认运行中 | “A 正在练习国际象棋” |
| 已核验的完成终态 | “A 的练习国际象棋交互已完成” |
| 已核验的取消终态 | “A 的练习国际象棋交互被取消” |
| 阶段或结果未知 | 保留原始状态，说明未确认阶段/结果 |

完成交互不能自动扩写为赢棋、技能提升、情绪改善或形成友谊；这些需要独立的运行证据。操作配置中的增量不能替代实测变化。

内部交互、社交调整或姿态步骤不一律解释为完整的玩家活动。合并多个事件为一段经历需要另有规则与证据，不能在文本层静默合并或删除事实。

## 4. 规则与资源基线

每条规则记录语义身份、输入要求、来源资源/定义身份、适用版本、语言、规范化方法、模板、回退方式、证据和验证状态。名称可作为辅助匹配信息，不作为永久唯一身份。

主要定义依据来自 EA 源码、tuning 与本地化资源。Atlas 帮助查找静态关系；不能仅凭静态目录推断实际状态。旧 Experience 词条只有在具体需要且重新核验后才采用。

游戏 `LocalizedString` 包含 hash/tokens，不保证转换成普通字符串就能取得客户端显示文本。STBL、动态名称、DLC/MOD 覆盖和语言都要按当前环境核验；无法解析时保留资源 ID 或原始标识。

源码入口：[localization](../../sims4-python/ea-source/EA/core/sims4/localization/__init__.py)、[resources](../../sims4-python/ea-source/EA/core/sims4/resources.py)、[InstanceManager](../../sims4-python/ea-source/EA/core/sims4/tuning/instance_manager.py)。提取数据与工具来自 `sims4-python` 时，应记录输入与生成版本，见[开发基线](reference-baseline.md)。

## 5. 输出与回退

输出可以包含规范化字段、文本、语言、规则版本、使用的原始记录/字段引用及未映射原因。原始事实保持可回查；是否把原始数据和文本同时导出由请求选择。

缺规则、缺字段、未知状态、资源版本不符分别标明。未知不默认成功，未实例化不默认不存在，默认值不伪装成已读取的实例值。

确定性转换在相同输入、资源与规则版本下应一致。规则升级后能够解释使用了哪一版规则，不静默改写先前导出的事实或历史输入。

## 6. 第一轮开发与验收

围绕首个贯通场景实现交互名称、目标名称、运行/完成/取消/未知，以及游戏时间的基本表达。未知词条保留原标识。选定需要的少量词条，不先整理全游戏语言资源。

离线样例覆盖同一行为的多种状态、缺字段、不同实例、未知规则、大整数身份及单位；游戏样例核对显示名称与数据来源。规则准确性与采集准确性分别验收，见[首轮实现与验收](implementation-and-validation.md)。

LLM 创作、主观记忆和 Overlay 展示属于后续消费者。基础语义转换不依赖运行时模型调用；旧阶段的完整消费流程保存在[历史语义与接口研究](archive/2026-09-research/semantic-catalog-and-context-api.md)。
