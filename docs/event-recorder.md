## 1. 职责与来源

记录在声明范围内实际观察到的游戏事件，保留身份、时间、来源和缺口，并按 Sim/Object 提供关联历史。记录模块拥有观测日志、规范事件和查询索引的状态；可以独立运行，也可向 Context 与语义化提供数据。

主要依据为 `sims4-python/ea-source/EA/`。先核对原生通知、实际发送点及对象生命周期；不能覆盖的具体需求再补 Hook。旧 Experience 只用于必要的接入经验参考，不要求继承六类经历、每 Sim 一个文件或其事件 ID/JSON 格式。

首轮只观察当前地块内已实例化的 Sim 和物件，同时接入行为经过、离散状态变化、连续状态采样及触发来源。触发来源保留 EA 原始枚举与中文分类，包括玩家意图由脚本续接等不能简单归类的情况；没有来源证据时标为未知，不推断动机或收集候选评分。

## 2. 第一版数据概念

以下是内部契约表达的概念。首版 schema v1、事件修订和物理文件组织见[接口登记](runtime-interfaces.md)与[运行说明](runtime-usage.md)。

| 概念 | 表达什么 | 边界 |
| --- | --- | --- |
| 原始观测 | 哪个源在何时报告什么，调用是否正常结束，原始身份和有界字段 | 保留可核验依据；不能把一次函数调用自动当成效果成功 |
| 共享事件 | 一次已确认发生的类型、参与实体、角色、阶段、结果、时间和来源观测 | 同一次发生可被多个源报告；关联需要经验证的发生身份 |
| 实体历史 | 某个 Sim/Object 与哪些事件有关，以及关系类型 | 作为事件引用与索引，不复制成多个独立事实 |
| 覆盖与持久化状态 | 记录范围、起止、缺口、已接收与已写入状态 | 不能用“没有记录”代替“没有发生” |

事件允许仅关联物件或世界系统，不要求虚构一个 Sim 主体。普通物件的历史是关联事件时间线；角色对它的主观印象由后续消费者表达。

主要交互进入默认事件历史，原生动画、姿态调整及辅助交互作为内部观测保留。只根据明确的交互/续接身份关联主交互；没有关联依据的内部观测保持独立，不按时间邻近合并。

## 3. 身份、时间与生命周期

Sim 持久 ID、物件实例 ID、物件定义/资源 ID 分开。跨运行或存档的身份连续性只有在验证后才能合并；第一轮可按独立运行范围隔离，并显式表示尚未支持的连续性。

同一来源记录重复投递，按来源范围与观测身份去重。不同通知报告同一次发生，根据已核验的交互/调用身份建立关联。相同演员、动词和相近时间不足以合并事件；同一 Sim 连续两次执行同名动作应保留两次发生。

生命周期需要容纳首次观测、运行中、完成、取消、失败及未知/未闭合情况。只看到终态时不补造开始时间；收到取消请求不等于观察到取消成功。阶段或证据后到时更新规范视图，并保留来源与修订依据。

游戏发生时间、观察时间和现实记录时间分开。数据采集前已开始、窗口内未结束、切换地块、读档及异常退出等边界应能表示缺口或截断。

## 4. 接入点与观察纪律

| 候选入口 | EA 源码依据 | 必须核验 |
| --- | --- | --- |
| 原生事件分发 | [event_manager_service.py](../../sims4-python/ea-source/EA/simulation/event_testing/event_manager_service.py)、[test_events.py](../../sims4-python/ea-source/EA/simulation/event_testing/test_events.py) | 谁发送、何时发送、payload、注册与注销；枚举存在不代表覆盖全部终态 |
| 交互生命周期与归档 | [interaction.py](../../sims4-python/ea-source/EA/simulation/interactions/base/interaction.py)、[interaction_archive_handlers.py](../../sims4-python/ea-source/EA/simulation/gsi_handlers/interaction_archive_handlers.py) | 运行身份、阶段、取消/异常及归档启用条件 |
| 统计量变化 | [base_statistic_tracker.py](../../sims4-python/ea-source/EA/simulation/statistics/base_statistic_tracker.py)、[base_statistic.py](../../sims4-python/ea-source/EA/simulation/statistics/base_statistic.py) | 实际前后值、通知范围、默认值与对象生命周期 |
| 物件状态与地块生命周期 | [state.py](../../sims4-python/ea-source/EA/simulation/objects/components/state.py)、[zone.py](../../sims4-python/ea-source/EA/simulation/zone.py) | 回调参数、重建/卸载、重复注册和注销 |

补充 Hook 时保持原返回值、原异常和调用协议。采集代码错误应隔离记录；不能吞掉游戏原异常，也不能把正常返回 `None` 与抛异常混为一谈。生成器需要单独验证迭代、异常和关闭协议。

操作配置中的数值、一次操作尝试和实测状态变化分别记录。只有真实前后值或等价证据才能表达实际增量；时间邻近仅是关联，不能冒充已证明的因果。

## 5. 持久化与查询

按运行目录保存追加 JSONL，事件修订可以离线重放。0.2.0 默认数量上限为 200,000，同时受 1,536 MiB 的事件正文/索引估算预算约束；后台队列上限 2,048 个任务和 32 MiB，单次运行日志与导出预算 2 GiB，磁盘预留 1 GiB。每次文件刷新和 fsync 成功后推进已写入序号，完整导出通过原子替换发布。预算适用范围和限制见[运行说明](runtime-usage.md)。

每个实体在记录器中拥有事件 ID 容器，统一事件表保存最新修订；一个事件可以被多个实体引用。首次观测时间索引保持稳定，更新修订不会改变其位置。旧历史查询保留最近更新顺序，新的查询支持首次观测/开始/结束时间、事件类型、变化字段、结果和交互 tuning ID 筛选。

分页冻结第一次查询时的事件版本、覆盖与持久化状态，后续新记录或修订不改变本次查询结果。快照默认在 120 秒现实时间后过期，可主动释放；数量、引用数和保守的版本保留内存均有上限。查询超预算只拒绝查询，记录仍继续。具体字段及命令见[接口登记](runtime-interfaces.md)。

至少区分已接收和已确认写入。成功写入前不释放唯一的待写记录；序列化失败、写入失败、队列溢出和损坏尾记录都有明确错误或缺口。未经确认的记录不能宣称耐久保存，重放按稳定身份处理重复。

首轮采用严格验证策略：过载时暂停受影响的采集，保留已有记录和错误证据，本次验收失败。不得自动降低采样频率或丢弃内部观测后继续宣称覆盖完整。每次运行独立落盘；重启或读档后开启新范围。

近期查询可以包含已接收的记录，但结果注明持久化状态。查询支持目标、事件范围和数量限制；“最近五条”可以是调试参数，不是固定数据契约。数据源关闭、没有匹配事件与记录覆盖不足分别表达。

## 6. 模块接口与验收

接口按能力定义：接收观测、查询事件、按实体列历史、读取覆盖与持久化状态、启停及释放订阅。事件记录不调用语义化决定事实是否保留，也不依赖 Context 消费者成功。

首轮验证同一发生的多次通知、连续独立动作、不同物件实例、完成/取消/未知、无 Sim 主体、写入失败、重复重放及运行范围隔离。集成场景和验证证据见[首轮实现与验收](implementation-and-validation.md)。

长期记忆、角色知情时间、印象和遗忘另见[后续研究](vision/README.md)。旧模型评估与迁移建议保存在[历史事件架构](archive/2026-09-research/event-memory-architecture.md)，不作为本模块前置要求。
