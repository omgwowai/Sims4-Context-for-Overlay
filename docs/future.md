# 未来方向

这里记的是接下来想做的事，还没都实现，也没有排死顺序。现在能用什么，看[架构与采集说明](architecture.md)。

现在已经有 [Overlay 读写、来源筛选和增量消费](public-api-v2.md)，普通旅行也能延续历史；事件分层、经历总结和自动文件导出也已实现。接下来优先验证真实下游 MOD 接入，并依据可回查样本扩充规则。[验证摘要](validation.md)记录了目前跑过的范围。

- **事件筛选与经历总结**：四层查询已进入 MOD 0.10.0 / API、SDK 2.2.0 源码，见[分层查询契约](event-views.md)；离线工具共用核心，保留完整来源、独立事件入口及清理结果。后续验证更多存档、玩法和大日志负载，定义派生视图的增量替换／删除协议及时间窗口查询，不要求下游采用统一叙事方式。设计依据保留在[实施计划](experience-recap-plan.md)。

- **接入反馈与兼容性**：优先跟进团队接入 SDK 时遇到的问题，继续验证新地块采集、连续旅行、长时间运行和第三方 MOD 组合；按实际场景补采集覆盖与中文说明。

- **已知的分类缺口**：2026-09-21 的约 36 小时样本中，Eddie 的 764 次 `commodity_Buff_ToddlerAwake` 数值变化明确关联 7 次 `chair_Nap`，各次小睡内部按游戏分钟重复；这是游戏反复操作，不是重复写盘，也不证明人物年龄。后续可基于精确资源和明确因果链接折叠展示，继续保留逐条证据。Nyssa 的自主电脑聊天选择器、Ava 的部分电视变体也仍需补充分类；待核查动作数不等于全部待核查证据数。

- **长期记忆、印象与遗忘**：以已记录事件为依据，保留派生来源和回查范围。同一次共同经历是共享事实，各人物的视角和主观记忆可以不同。
- **角色知识**：区分事件发生时间、感知时间和知情时间。同场、附近或被事件索引关联，不自动等于目睹或理解。
- **历史状态重建**：只有选定字段具备有效基线、连续变化记录及可验证重放时，才考虑恢复某个时刻的状态；当前快照与事件说明不能替代这些条件。
- **Overlay 消费**：消费者读取 Context，生成旁白、独白、回顾或交互界面；生成、提交显示和确认显示分别记录，检查 session、目标及 request ID，丢弃过期结果。
- **生成事件与游戏执行**：区分模型提案、执行前核验、真实执行和结果回录，不把生成的故事当作已发生事实。

例如共同吃一顿饭可以形成一条共享事实和多个人物视角；谁知道、如何评价、以后怎样记住，需要独立证据或明确标记的派生规则。当前事件记录不预设“长期记忆系统”或旧 Experience MOD 依赖。

旧图解、研究草案和过程记录通过 Git 历史回查。新的能力先补当前契约与验证，再讨论展示和玩法。
