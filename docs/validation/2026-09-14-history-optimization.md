# 历史查询优化与容量验证（0.2.0）

日期：2026-09-14。分支：`zixuan/first-runtime-implementation`。

本报告保存 0.2.0 当时的离线测量与未部署状态。此后 0.3.0 增加原生查看窗口并按要求安装，见[后续记录](2026-09-14-inspector.md)；当前 dist 和安装包不必与本报告的旧摘要相同。

## 状态与边界

已完成实体关联索引、时间/类型筛选、固定版本分页、资源预算及构建。**按本次要求只做离线验证，没有启动或控制游戏，没有替换用户 Mods 中已验证的 0.1.0。** 0.1.0 的[实机验收](2026-09-14-first-round.md)保留为历史证据，不能作为 0.2.0 已游戏验证的证明。

本次没有实现跨运行合并、数据库历史索引、区间重叠搜索、增量修订订阅或跨 MOD 公开 SDK。

## 实现结果

- 统一事件表保存当前修订，各实体维护事件 ID 引用；同一事件只保存一份正文，新增参与实体补上关联。
- 首次观测时间索引使用稳定的游戏 ticks 和首次接收序号，支持二分定位。开始/结束时间查询筛选该实体候选，避免漏掉早开始、晚结束的交互。
- 保留 `co.history` 最近更新顺序；新增 `co.history_query`、`co.history_next`、`co.history_close`。
- 可按事件类型、变化字段、结果、tuning ID、内部层次和时间筛选；时间范围为 `[from, to)`，同一时刻的排序稳定。
- 首次查询固定匹配成员、修订版本及覆盖/持久化状态；游标可重试，最终页保留至释放/过期。退出地块或重启释放查询，游标不跨运行。
- `Collector.collect` 可通过 `history_query` 组合筛选后的第一页。后续历史页面保持原查询版本，不重新读取当前快照。
- 日志重放去重改为保留记录摘要，序号检查改为线性推进；可省略观测列表，降低大日志的额外内存。

数据结构和命令参数见[接口登记](../runtime-interfaces.md)与[运行说明](../runtime-usage.md)。

## 200,000 条事件的资源测量

使用原始 2,340 条事件的实际结构，按其交互/状态变化比例扩展至 200,000 条，并实际构建新索引。新的事件 ID 和首次观测排序时间是合成的，其他字段沿用样本结构。测量脚本为 [benchmark_history.py](../../scripts/benchmark_history.py)。

测试机物理内存约 32 GB；开始检查时约 17 GB 可用，C 盘约 791 GB 空闲。完整结果与构建清单见[机器可读记录](2026-09-14-history-optimization.json)。

| 测量 | 结果 |
| --- | --- |
| 已加载事件 | 200,000，未触发预算失败 |
| 实体关联引用 | 226,610 |
| 事件正文与索引计量 | 1,488,825,183 字节，约 1.49 GB / 1.39 GiB |
| 测试进程私有内存 | 1,542,356,992 字节，约 1.54 GB / 1.44 GiB |
| 建立 20 万条索引 | 约 9.97 秒，离线批量构建 |
| 最近 50 条：旧全局扫描 | 7 次测量中位约 103.75 ms |
| 最近 50 条：实体索引 | 相同结果及副本转换，中位约 0.39 ms |
| 时间筛选首次分页 | 约 2.15 ms；检查 729 个候选，匹配 575 条 |
| 后续页面 | 中位约 0.44 ms |
| 日志体积推算 | 按旧实机运行的观测/修订比例，20 万条约 494 MB |

查询时间是独立 Python 进程中的测量，未包含游戏服务读取、真实游戏负载、文本语义化或文件写入。日志体积是比例推算，不是本次实际写入了 494 MB，也不是对新版本字节量的精确承诺。新增字段、事件构成和修订次数会改变实际大小；实际写入受字节预算限制。

仅复制复杂交互样本时，20 万条的计量可约为 2.54 GB，高于默认记录内存预算；因此会先暂停，不能承诺所有场景都能存满 20 万条。

## 默认预算与失败语义

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| `history_capacity` | 200,000 | 单次运行的逻辑事件数 |
| `history_memory_mb` | 1,536 MiB | 事件正文与索引的保守 Python 分配估算 |
| `history_query_limit` | 8 | 同时保留的查询快照 |
| `history_query_max_refs` | 100,000 | 所有查询快照的引用总数 |
| `history_query_memory_mb` | 256 MiB | 快照保留版本的保守计量，当前事件表中的共享版本也计入 |
| `history_query_ttl_seconds` | 120 秒 | 按现实时间过期，可主动关闭 |
| `writer_capacity` / `writer_memory_mb` | 2,048 项 / 32 MiB | 已排队与写入中的文本任务受数量和字节约束 |
| `run_output_mb` | 2,048 MiB | 一次运行接受的日志与导出输出预算 |
| `disk_reserve_mb` | 1,024 MiB | 写入前检查的磁盘预留空间 |

数量上限与字节预算同时生效。记录或持久化预算不足时暂停并报错，已有磁盘记录保留，未写完的数据不确认成功；只超出查询预算时拒绝查询，记录继续。已结束运行的文件不自动删除，磁盘预留检查也约束后续运行继续写入。

内存计量用于控制模块规模，不是整个游戏进程的 RSS 硬限制；它不包含游戏自身、其他 MOD、所有临时分配或内存分配器开销。仍需后续实机测量。默认较宽的快照查询可能先达到预算，可以缩小时间/类型范围后再分页。
