# 游戏内状态与历史窗口：使用及手动试验（0.3.2）

日期：2026-09-14。当前 0.3.2 调整首页按钮顺序，并将状态及历史列表改为横向文字行，去掉每行的空图标／红色 X 及预留缩略图区域；长详情用文字正文。沿用默认关闭需求变化历史、实体索引、分页及 200,000 条上限。已安装，用户实看后确认调整已足够好；助手实测的具体范围与截图见[布局验证记录](validation/2026-09-14-inspector-layout.md)。下方是完整操作清单，不表示所有条目均在本轮实测通过。

## 1. 安装位置与启动

已安装文件：

```text
C:\Users\ZixuanMin\Documents\Electronic Arts\The Sims 4\Mods\ContextOverlay\ContextOverlay.ts4script
```

仍然只有一个脚本包，不依赖 XML Injector 或额外资源包。使用游戏原生选择器，不是可拖动、常驻的自定义 Overlay。

1. 启动游戏，确认“启用自定义内容与模组”和“允许脚本模组”已开启。本次安装前读取到两项均已开启，没有修改选项。
2. 读取存档，进入生活模式和实际地块，等待几秒完成实体登记。
3. **普通点击当前地块上的 Sim 或物件**，在交互菜单里找 **“查看状态与历史”**。必要时翻到“更多选择”。不需要 Shift，也不需要开启作弊。
4. 首页直接阅读近期事件文字。按钮从上到下为 **“当前状态 → 历史事件 → 刷新 → 关闭”**。
5. 状态分类、字段与历史改为横向文字行，**点击一行直接进入**；返回、筛选、上一页和下一页也是列表操作项，内容超出窗口时向下滚动。快照时间、筛选或页数显示在表头，鼠标停在表头可查看完整说明。长详情的“返回／上一段／下一段／关闭”位于正文下方。
6. 点击“关闭”、按 Esc 或右上角关闭按钮结束查看。原生窗口会暂停游戏；关闭后恢复打开前的速度状态。

只为当前地块内、已实例化且未隐藏的实体提供入口；场外 Sim、世界地图、建筑模式、库存中的特殊对象、无法点击或覆盖原生菜单的对象不在第一版保证范围。

## 2. 窗口内容

| 页面 | 内容与操作 |
| --- | --- |
| 状态与历史 | 固定查看的实体名称、读取时间、记录状态、状态摘要；最近 5 条主要事件按“时间｜内容”逐行显示，较长内容带省略号，完整内容从“历史事件”进入 |
| 当前状态 | Sim 的身份、时间、位置、需求、当前交互、Buff、范围内关系；物件的身份、时间、位置、常用状态 |
| 状态分类详情 | 每页最多 15 个横向文字条目，名称与摘要同一行显示；点击继续展开，长说明每段最多 700 字符，通过“下一段”读完 |
| 历史事件 | 默认近 24 游戏小时、主要事件、首次观测时间倒序；每页 15 条，选择事件查看详情 |
| 历史筛选 | 近 1／6／24 游戏小时或本次运行全部时间；全部／交互／状态变化；显示或隐藏内部步骤。每次选中一项后立即应用 |
| 事件详情 | 中文解释、参与者与可观测来源／结果、首次观测和开始／结束／最近观测时间、采样区间、事件 ID、修订及查询时的写入状态 |

需求值沿用游戏内部数值，**不是百分比**。Buff 包含游戏实际提供的记录，其中可能有隐藏 Buff 或未解析的调试名称。物件仅展示已接入目录的状态；关系仅覆盖当前观测范围内的已存在关系。未采集、未支持、读取失败和空列表有不同含义。

从 0.3.1 起 `record_need_changes` 默认为 false：后台不采样记录 `needs.*` 的连续变化，因此它们不再占据新运行的近期事件。Context 的当前需求读取、交互、Buff、物件状态、关系标记和关系数值采样继续工作。旧运行日志不修改，旧日志中已有的需求变化仍保留。

“最近 5 条”按最近更新排序；历史浏览按首次观测时间排序。一个较早开始、刚刚结束的交互可能出现在概览前面，而在历史列表中位于更早的位置。

窗口从运行时直接查询内存数据，不执行控制台导出，也不会为每次查看写一个 Context JSON。原有后台日志记录继续按记录器规则工作。查看交互本身不会进入生活事件历史或当前交互快照。

## 3. 建议按这个顺序试验

### A. 入口与对象身份

1. 点击当前操控的 Sim，打开窗口，核对姓名及需求。
2. 关闭窗口，点击另一个当前地块内的 Sim，核对标题和内容确实属于被点击者。
3. 点击冰箱、台面或食物，核对窗口切换为物件字段；同类两个物件应该各自显示自己的状态与历史。
4. 核对普通游戏交互仍然可用，并且没有重复的“查看状态与历史”入口。

通过标准：菜单可见、窗口打开、目标正确、原有菜单正常。部分特殊物件没有可读取的常用状态，窗口应说明空结果或不适用，不能伪造状态。

### B. 状态与事件详情

1. 点击“当前状态”，逐项查看需求、Buff 和关系。数量超过一页时试“下一页／上一页”。
2. 关闭窗口，让 Sim 做饭、吃饭或进行普通交互。
3. 再次打开窗口，查看“历史事件”，把类型筛选为“交互”，找到刚才的操作并打开详情。
4. 切换为“状态变化”，检查可观测的 Buff、物件或关系变化；需求值变化默认不应生成事件。回到首页点击“刷新”，仍应能看到最新的当前需求值。

通过标准：中文描述能与游戏中实际发生的行为对照，近期事件没有持续的需求采样刷屏，当前需求仍能刷新。关系数值仍默认每 5 游戏分钟采样；有采样区间的变化不能直接证明由某一次活动导致。

### C. 分页、刷新与退出

1. 累积超过 15 条匹配事件后，打开历史，依次试下一页、上一页、事件详情和返回。
2. 历史页面固定在第一次查询时的事件版本；要看后来的完成或取消结果，点击“刷新历史”。
3. 可故意在窗口停留超过 120 秒现实时间，再翻页。应提示页面过期，点击“刷新历史”后恢复；游戏暂停也计入这 120 秒。
4. 关闭窗口后重新打开，应能正常查询。旅行到另一个地块再打开，应进入新的记录范围，而不是继续旧游标。

通过标准：导航正确，页面不过度堆叠；正常翻页无重复／遗漏；过期和范围改变有明确处理。当前实机覆盖范围见验证记录；旅行、不同分辨率和特殊物件可继续按此清单补测。

## 4. 暂时找不到入口或发生错误

先打开控制台 `Ctrl + Shift + C`：

```text
co.status
co.inspect
```

`co.status` 应显示 `module_version` 为 `0.3.2`，`config.record_need_changes` 为 false，`inspector.state` 为 `ready`、`menu_hooks` 为 `2`。`co.inspect` 是备用入口，打开当前操控 Sim 的同一个窗口；有 ID 时也可使用 `co.inspect sim ID` 或 `co.inspect object ID`。关闭控制台后查看窗口。

- **控制台入口可以打开，普通点击菜单不出现**：优先记录目标类型及是否装有其他菜单类 MOD，说明是菜单接入问题。
- **`inspector.state` 为 `failed` 或 `last_error` 有内容**：查看下方日志；UI 故障与记录器状态分开报告。
- **历史提示查询范围过大**：改成近 1／6 小时或筛选单一事件类型。20 万条是记录上限；查询快照仍受单独内存预算约束。
- **历史显示记录已暂停**：查看 `co.status` 的 recorder 错误。不要将暂停后的空历史误认为没有发生事件。
- **标题是旧版本**：完整退出并重新启动游戏，确认 Mods 中只有一份 ContextOverlay 脚本包。

日志：

```text
C:\Users\ZixuanMin\Documents\Electronic Arts\The Sims 4\ContextOverlay\runtime.log
```

正常接入会写 `INSPECTOR READY`，打开窗口会写 `INSPECTOR OPEN sim:...` 或 `object:...`。发生异常可提供操作步骤、游戏版本、出问题的实体、界面表现，以及日志末尾相关错误。若生成 `lastException.txt`／`lastUIException.txt`，也保留它们。

## 5. 配置、安装记录与回退

`ContextOverlay/config.json` 新增可选项 `"inspector_enabled": true`，默认开启。现有配置只有 `development_driver: false`，本次没有修改。将该选项设为 false 并重启游戏可以关闭窗口和菜单入口，保留其他模块。

如果之后需要重新记录需求变化，可以在配置中添加 `"record_need_changes": true`，重启游戏后按既有采样间隔记录。省略此项即使用 false；开启与关闭均不影响 Context 的当前需求字段。

安装脚本为 [scripts/install.py](../scripts/install.py)，核对构建摘要、检查游戏进程、备份旧包后仅替换本项目脚本包；安装记录在 `.validation/inspector-install.json`，包含旧包备份的绝对路径和新旧摘要。

需要回退时，先退出游戏，再用安装记录中 `backup` 指向的旧包覆盖上面的安装文件。旧包备份保存在仓库 `.validation/install-backups/` 下，没有放进 Mods，避免重复加载。

本轮按用户授权进行了实机界面检查，助手退出各次测试时选择不保存，最后一次由用户关闭游戏。结束时 30 个原存档摘要一致、无新增存档文件，配置不变，Options.ini 仅游戏启动计数增加。用户确认本轮布局调整足够好；完整分页流程和最终表头悬停说明未由助手逐项复测，见[0.3.2 布局验证记录](validation/2026-09-14-inspector-layout.md)。此前的[0.3.1 改进记录](validation/2026-09-14-inspector-refinement.md)保留当时仅离线检查的结论。
