SIMS4-CONTEXT / 架构设计

让游戏事件拥有连续的解释

游戏负责行为与后果，Overlay 根据当时状态和已记录经历生成对白。Experience 保留事件与叙事，帮助下一次解释接上此前的故事。

Markdown 文档

按“现在 → 未来”阅读。蓝色虚线表示只读观察，绿色表示经历保留与检索，紫色表示解释生成与可选叙事写回。窄屏可横向滚动。

Explanation Context = 事件相关的 Game Context 快照 + 当前 Event + 检索到的相关 Experience

状态演化是概念抽象

Context 包括队列、计时器与运行中的交互。Event → Context 表示事件对应的游戏过程产生后果；未来状态也来自原有状态延续和时间推进。图中没有展开所有引擎回调。

记录与展示独立

在明确采集范围内记录可观察事件，筛选后才触发气泡。生成绑定事件相关快照；展示前检查场景是否仍然适合。后续 Event 按同一模式继续记录。

解释层维护自己的连续性

Experience 与 Overlay 初版只影响后续解释。生成对白需要标明来源；“说过要再来”可以成为叙事约定，但不会因此自动安排一次游戏内约会。

Experience 内的记录保存什么后续如何使用
Event Log · 事实已观察的参与者、时间、情境、行为与实际结果作为回忆的事实依据，保留原始来源
Memory · 派生记忆共同经历、摘要、印象及关联事件引用帮助检索与组织回忆，区分事实、摘要和推断
Overlay Record · 叙事实际展示的内容、说话者、可知角色与关联事件延续说过的话；内容中的陈述不自动成为游戏事实

同一个新事件，可以因共同经历而产生不同的对白。回忆来自已有记录，措辞同时受当前关系、情绪和角色视角影响。

确认“第一次”的依据

示例假设已有可信依据确认第一次约会。若只有从某时点开始的局部记录，就使用“那次约会”，不能把最早采到的一条记录直接当成人生第一次。

跨食物实例检索

保存具体食物实例，也保存“牛排”等类型标签。下次可以是另一份牛排、另一家餐厅；同一对角色与相关主题仍能检索到这次共同经历。

尊重角色的知识范围

共同亲历可以用于双方回忆。内心独白与只给玩家看的旁白，不会自动成为另一角色知道的信息；对白是否被获知需要明确记录规则。

本页是建议架构与示意情节。采集范围、游戏内气泡呈现和延迟处理仍需实机验证；叙事解释不等同于已经证实的 Autonomy 决策原因。页面图形与交互均可离线使用。
