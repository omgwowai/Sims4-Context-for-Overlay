# 面向 LLM Overlay 的运行时 Context 分类

版本：v0.1。日期：2026-09-11。

本文先把 Overlay 理解为叠加在既有游戏过程上的内容，例如角色对白、内心独白、事件解说、记忆、情节延续，以及由 MOD 支持的玩法反馈。分类也适用于屏幕上的展示层；具体展示形式可以后续确定。本文只讨论输入数据，不设计 Prompt。

分类依据是“LLM 需要理解的游戏含义”。它是一份可扩展的 Context 目录，不是已实现的采集接口清单。来源沿用[参考资料基线](reference-baseline.md)；本轮补查了角色知识、关系、状态、职业、物件和资源等源码入口，没有运行游戏验证。

如果按获取方式和具体 API 选择采集方案，见 [Context 的技术获取方式与接口分类](context-acquisition-interfaces.md)。该文档按查询、订阅、Hook、GSI、资源和持久化等技术入口组织，与本文的内容类别交叉关联。

## 1. 分类总览

建议分为 **12 类内容 Context**，并为它们统一附带时间、身份、来源、角色视角和采集状态等元数据。

| 编号 | 类别 | 帮助 LLM 回答的问题 | 典型内容 |
| --- | --- | --- | --- |
| C01 | 世界、时间与场景 | 现在何时何地，周围是什么环境？ | 游戏时间、地块、场所类型、空间关系、天气、季节 |
| C02 | 角色身份、人格与能力 | 这个 Sim 是谁，有什么特点、会做什么？ | 身份、年龄阶段、物种、人格、好恶、技能、外观引用 |
| C03 | 角色即时状态 | 他现在身体和情绪如何？ | 需求、情绪、Buff、健康、生理或特殊形态状态 |
| C04 | 人际关系与社会结构 | 谁和谁是什么关系？ | 亲属、朋友、恋爱、关系轨道、Sentiment、家庭与群体成员 |
| C05 | 当前活动与已表达意图 | 谁正在做什么，接下来已经安排了什么？ | 正在执行的交互、队列、目标、参与者、来源、取消与中断 |
| C06 | 情境、目标与生活进程 | 这段活动为了什么，处于什么阶段？ | Situation、身份职责、目标、愿望、职业、学业、日程与里程碑进度 |
| C07 | 物件、资源与经济 | 有什么可用的东西，状态和归属如何？ | 场景物件、库存、食物、制作进度、所有权、资金、资产与消耗 |
| C08 | 感知与角色知识 | 这个角色实际感知了什么、知道什么？ | 广播命中、反应、已知特征/职业、获知事件与知识来源 |
| C09 | 近期事件、变化与因果 | 刚刚发生了什么，带来了什么结果？ | 交互终态、状态增减、加入离开、里程碑触发、原因与后果 |
| C10 | 历史经历、记忆与印象 | 过去发生过什么，这件事对他意味着什么？ | 可追溯经历、共同历史、重复行为、物件印象、长期记忆摘要 |
| C11 | 行动条件、规则与决策依据 | 此刻有哪些相关选择，哪些条件成立？ | 可供评估的交互、测试结果、阻碍、资源成本、候选评分与选择记录 |
| C12 | Overlay 与扩展 MOD 的持续状态 | 叠加内容已经推进到哪里，需要接续什么？ | 已显示对白、已建立设定、未解决情节、玩家实际选择、效果执行结果 |

几个主类之间的分工：C02–C07 主要描述当前状态；C09 记录发生与变化；C10 保留和组织历史；C08 记录某个角色对事实的感知与知识关系。一个事件可以更新多个状态类，数据通过引用关联，不需要复制为几个独立事件。

## 2. 来源与可获得程度

“运行时提供给 LLM”可以组合以下来源。静态资源用于解释当下的实体和规则，历史数据需要在运行期间持续积累。

| 来源 | 能提供什么 | 本文如何标注 |
| --- | --- | --- |
| 游戏运行时对象、服务与 tracker | 当前角色、关系、物件、情境等状态 | **读取入口**：在 EA 源码找到入口，具体字段仍需验证版本、实例状态和 DLC 条件 |
| Observer / Experience 采集器 | 部分快照、交互、效果、决策与经历 | **已有采集**：参考项目已有相关实现；不表示本项目已经接入，也不表示该类全部字段已覆盖 |
| 生效中的 tuning、资源与本地化表 | 名称、类型、规则参数、说明及资源关联 | **资源补充**：按当前版本、DLC、MOD 覆盖结果解析，不能把静态配置当成实时结果 |
| 本项目或其他 MOD 的日志与状态 | 采集后的历史、叠加剧情、实际玩家输入等 | **需新增记录**：由对应系统持续保存或提供适配器 |
| 基于观测的计算或 LLM 结果 | 趋势、摘要、印象、推断 | **需派生**：保留依据、算法/模型版本，与游戏直接事实分开 |
| 客户端、截图或专用 UI 接口 | 实际屏幕可见内容、镜头、界面状态 | **客户端扩展**：按展示需求额外接入，当前 Script Mod 采集不能视为已覆盖 |

以下列出的字段是候选数据范围。对于只找到服务或类的项目，不据此承诺其中所有字段都能无损读取；未安装的 DLC 和不支持的 MOD 应明确返回不适用或未支持。

## 3. 各类 Context 的内容与边界

### C01 世界、时间与场景

**内容：**

- 游戏日期、星期、时刻、昼夜阶段，以及与当前场景有关的日历信息。
- world / region / zone / lot 的身份和名称、住宅/餐厅/公园等场所类型、适用的地块特征。
- 场内相关实体的位置、楼层、房间归属、相互距离；房间与可达关系需要对应接口支持。
- 当前天气、季节、环境状态；当前场景中的火灾等事实可通过事件和对象状态引用。
- 对生成内容有影响的环境效果，例如正在生效的音乐或气味广播，以已捕获的来源与作用记录表达。

**用途：**让对白、描写和叙事符合当前场景与时间。

**来源与现状：**已有 zone、位置和游戏时间的部分采集；天气/季节存在服务入口，需按 DLC 接入。更新以换地块、时段变化及环境变化为主，空间细节按需刷新。

**边界：**在附近、同房间、可达、在屏幕内和被角色看见是不同事实。家具名称只能辅助描述，不能单独证明房间用途或角色感受。

### C02 角色身份、人格与能力

**内容：**

- Sim 持久身份、显示姓名、年龄阶段、物种、性别等游戏已保存的身份属性。
- 人格特征、游戏明确保存的喜欢/不喜欢、有关偏好及特殊类型身份。
- 技能类型、当前等级、熟练度、已经解锁的能力；特殊能力依赖对应玩法。
- 当前服装类别、外观资源或肖像引用，在需要服饰描写、角色展示时按需提供。
- 家庭、职业和群体等身份通过 C04/C06 引用，避免在画像中保存第二份独立状态。

**用途：**让角色表现有差异，并让生成内容符合年龄、能力和已有设定。

**来源与现状：**SimInfo、TraitTracker、Skill 等读取入口；Observer 已采集部分 traits，Experience 的语义层使用人格快照。身份和人格按变更更新，技能按升级或相关活动刷新。

**边界：**必须区分人格 Trait 与隐藏、奖励、临时或系统用途的 Trait。特征和技能对行为有解释价值，但不能直接证明角色此刻的想法。外观资源标识也不等于已取得准确的视觉描述。

### C03 角色即时状态

**内容：**

- 饥饿、精力、社交、娱乐、卫生、膀胱等当前适用需求，以及原始量、区间或归一化值的定义。
- 当前情绪、情绪强度，以及相关 Buff 的类型、来源、持续时间或到期信息（能够取得时）。
- 睡眠/清醒、疾病、怀孕、死亡等玩法保存的状态；避免从一个动作名称替代读取实际状态。
- 超自然或 DLC 特有资源、状态和阶段，例如某种形态或专属能量，仅在该角色适用时存在。
- 有观测支持的变化趋势，例如需求正在下降；趋势属于派生值，保留时间窗口。

**用途：**生成符合角色当下处境的对白、独白、反应和事件解释。

**来源与现状：**statistic/commodity tracker、BuffComponent、SimInfo 专用 tracker；已有部分需求快照与 Buff 事件采集。采用快照加变更，关键生成时点刷新。

**边界：**Buff 增删与当前情绪不是同一个事实，多项 Buff 可能共同影响情绪。数值方向和范围按字段定义提供，不能假设所有需求都共用一个刻度。内部状态可读也不等于其他角色知道它。

### C04 人际关系与社会结构

**内容：**

- 关系两端的 Sim、亲属与谱系、伴侣或婚姻状态、家庭成员关系。
- 友谊、浪漫等关系轨道，明确的 Relationship Bit，以及双方各自的 Sentiment。
- 当前相关的吸引力、兼容性等玩法指标，按版本和 DLC 标记适用范围。
- 俱乐部、组织、社交群体成员及角色；本轮活动中的临时职责归 C06。
- 关系对外是否已被某个角色知道，通过 C08 的知识引用表达。

**用途：**决定互动的熟悉程度、社会背景与关系发展连续性。

**来源与现状：**RelationshipTracker/关系服务、家庭与群体服务；Experience 已有部分关系效果记录，但完整关系快照和变化监听仍需补充。按相关人物加载，关系变化时更新。

**边界：**保留关系方向、共享字段与单向字段的区别。A 对 B 的情感不能自动复制为 B 对 A 的情感，数值变化也不能直接替代“已经成为情侣”等显式状态。

### C05 当前活动与已表达意图

**内容：**

- 正在运行、排队和过渡中的交互：名称、类型、actor、target、参与者、开始时间和生命周期阶段。
- 当前姿态、携带对象、移动或交互目标，以及已记录的执行进度、中断和取消原因。
- 交互来源：玩家操作、自主决策、脚本、反应或其他已识别来源。
- 可定位的 continuation、group 或父交互关系，用来识别一个活动由哪些步骤组成。
- MOD 接收到的明确玩家选择或操作记录，可作为已表达意图；未经记录的玩家心理不在此范围内。

**用途：**让 Overlay 接上当前动作、避免描述已经结束的行为，并区分玩家安排与 Sim 自主行为。

**来源与现状：**Sim.queue、si_state、InteractionContext，以及 Observer 生命周期采集；Experience 主要提供终态经历。按入队、开始、结束、中断等变化更新。

**边界：**队列表示当前安排，可能被取消；不保证将来一定完成。移动目标和自主评分不等于自然语言意义上的意图。角色对白的具体内容也不能仅由一个“聊天”交互标签还原。

### C06 情境、目标与生活进程

**内容：**

- 当前 Situation 实例，例如约会、婚礼、聚会、工作活动；包括成员、job/role、阶段、计时和目标进度。
- 愿望、抱负、当前里程碑目标及完成进度；保留“系统分配、玩家选择、MOD 添加”等可验证来源。
- 职业和学业状态、等级或表现、工作/上学安排、当前是否在岗、已存在的任务与期限。
- 节日、预约、比赛、旅行等已经登记的安排，以及生命周期或其他玩法的推进阶段。
- 当前目标与相关实体、活动、事件之间的引用，例如“这次吃饭发生在该约会实例中”。

**用途：**支持有阶段的情节，让内容围绕正在进行的生活目标和活动推进。

**来源与现状：**Situation、career_tracker、whims/aspirations 及对应玩法服务；已有部分 Situation 进出记录，其余需要专用适配。按阶段、成员和目标变化更新，日程低频刷新。

**边界：**同一个 Sim 可以同时属于多个 Situation，不能只留一个情境槽。系统调度的“路人”“服务人员”情境不一定是角色主观目标。已安排的未来事项是计划，不能写成已经发生。

### C07 物件、资源与经济

**内容：**

- 物件实例、定义/型号、名称、类型、位置、所有权，以及部件与宿主的关联。
- 相关对象状态，例如食物品质与份数、清洁程度、损坏状态、开关、占用/预订状态；只有对象实际支持时才有这些字段。
- Sim、物件和家庭库存中的内容、数量与容器关系，以及可见/隐藏库存的区别。
- 制作中的产物、进度、配料与已投入资源；操作能否执行及规则成本归 C11。
- 家庭资金、物件价值、账单、经营或玩法专用资源；保留资源的归属主体与单位。

**用途：**为可互动场景、物件故事、经济压力和行为后果提供具体依据。

**来源与现状：**object_manager、StateComponent、InventoryComponent、FamilyFunds 与专用组件；已有采集只涉及其中一部分。对象创建/删除、状态变更和资源增减时更新，检索限定相关范围。

**边界：**场景中有物件不等于角色可使用它；锁门、占用、所有权等限制需另查。物件型号与单个实例必须分开，不能把另一份食物或另一把同型号椅子的经历混进来。

### C08 感知与角色知识

**内容：**

- 真正捕获的广播作用、反应触发和参与记录，以及感知来源、作用对象和发生时间。
- 游戏关系知识：某 Sim 是否知道对方的特征、职业、关系状态等，以及可取得的已知内容。
- MOD 记录的亲历、目睹、被告知事件；获知方式、告知者及对应事件引用。
- 角色已知事实、过时知识、由 Overlay 建立的信念或猜测，分别标明来源和性质。

**用途：**支撑第一人称对白和记忆，表达信息差、误解、秘密与逐步获知。

**来源与现状：**已有 Broadcaster/Reaction 的部分采集；EA `SimKnowledge` 明确保留 known_traits、knows_career 等知识状态。完整的“谁知道每件事”需要新增记录，推断出的信念属于派生或 Overlay 数据。按感知与知识变化更新。

**边界：**`SimKnowledge` 是特定玩法知识记录，不是完整心智模型。某些已知内容通过知识标记再查询对方当前状态取得，不能一概视为“当时听到的历史值”。同场或距离近不能单独证明目睹，也没有据此证明所有游戏对话都能获取逐字内容。

### C09 近期事件、变化与因果

**内容：**

- 最近窗口内的交互完成/取消、感知、状态变化、加入离开、决策与显著玩法事件。
- 事件主体、对象、参与者、游戏时间、所处情境和世界分支。
- 实际前后值或 delta、效果是否成功、相关资源消耗及里程碑触发。
- 已核验的直接触发关系、系统来源、贡献关系；同时保留时间邻近和同情境关联的不同类型。
- 当前仍未闭合的交互或区间，以及已经识别的采集缺口。

**用途：**让 Overlay 对刚发生的变化及时反应，并解释可追溯的后果。

**来源与现状：**Observer、Experience 的事件采集，可复用六种经历类型作为部分视图；纯物件、家庭或后台事件需要补采。按事件增量更新，窗口按任务选择。

**边界：**交互调用、效果尝试、实际状态变化、情绪结果是不同事实。`parent_id` 不是所有因果的完整表达，缺 parent 也不必然是漏采。现实中发生但尚未采集的事件不能通过 LLM 补成事实。

### C10 历史经历、记忆与印象

**内容：**

- 采集起点之后留存的个人经历、双方共同经历、地点和物件的有关历史。
- 游戏当前保留的里程碑、关系或其他记忆性记录，注明它们的原生含义和保留精度。
- 可从事件重算的使用次数、成功/失败、关系变化、重复行为与时间趋势。
- Experience 的物件印象卡、好恶标签，以及 MOD 生成的长期记忆摘要。
- 第一人称的意义解释，例如“确认关系那次用过的物件”，附实际事件和情境证据。

**用途：**让内容具有长期连续性，支持回忆、旧事重提和经历影响后续表现。

**来源与现状：**已有 Experience 折叠与语义记忆能力；其他历史需要持续记录，统计与摘要属于派生。随新证据更新，生成时按角色、对象、情境检索相关片段。

**边界：**历史事件与近期事件是同一事实库的不同时间视图，不重复建立事实。印象与好恶标签不自动等于游戏原生的喜好；摘要不能替代证据。不同存档及读档回滚分支的记忆必须隔离。

### C11 行动条件、规则与决策依据

**内容：**

- 相关实体提供的交互定义、可供评估的候选、目标及参与者规格。
- 已实际执行的 Test 结果、参与者解析、通过/失败条件、已知阻碍和取得结果的时间。
- 与候选有关的技能、年龄、关系、物件、资源、冷却或路径条件；具体约束按定义存在与否提供。
- 当前生效的规则说明、tuning 参数、预计成本或效果，与实际执行结果分开。
- 某次 Autonomy 请求的候选池、评分因素、随机选择、选中与推送结果。
- 若 Overlay 会触发游戏效果：扩展 MOD 当前支持的效果类型、参数范围和可用状态，作为能力数据提供。

**用途：**为可落地的选择、行为解释和玩法延续提供依据。

**来源与现状：**tuning/资源补充、交互测试与 Autonomy；Observer 已有较丰富的候选、Test Readset 和评分证据。按请求记录，相关状态变化后重新判断结果是否仍有效。

**边界：**一次 Autonomy 请求的候选不等于全部玩家菜单或所有理论行动；没进入候选也不等于被禁止。测试通过不保证稍后执行成功。候选已评估、选中、推送、开始和完成分别保存。读取时优先复用真实执行记录，不默认重新运行可能带随机或副作用的逻辑。

### C12 Overlay 与扩展 MOD 的持续状态

**内容：**

- 先前生成、实际显示或播放的对白、旁白、独白及其关联角色和事件。
- 由 Overlay 明确建立并持久保存的人物设定、约定、冲突、未解决情节与阶段进度。
- 玩家在 Overlay 界面中实际选择的选项、提交的文本和后续反馈。
- MOD 请求的游戏效果及其状态：提出、发送、拒绝、执行中、已由游戏结果确认。
- 第三方 MOD 自有的玩法状态与计数；通过命名空间和适配器接入后，相关事实仍归入 C01–C11。

**用途：**让多轮生成接续已有内容，避免重复开场、遗忘约定或提前描述尚未执行的结果。

**来源与现状：**需由 Overlay/对应 MOD 新增记录；不是游戏本体天然提供的数据。按生成、展示、玩家输入和执行确认更新。

**边界：**“生成过”不等于“显示过”，“说过”不等于“游戏事实已经改变”。例如 LLM 生成求婚对白、玩家看到对白、游戏关系变成订婚，应保留为不同状态并关联。角色是否听到/获知 Overlay 内容还需要 C08 的记录规则。

## 4. 所有类别共用的元数据

以下属性与 12 个内容类别正交；用于判断一项信息是否属于当前世界、是否新鲜、是否适用于当前角色视角。

| 维度 | 至少需要表达的内容 |
| --- | --- |
| 身份与作用域 | 游戏版本、存档谱系、读档分支、session、zone 加载代次、实体 ID、定义 ID；64 位 ID 用字符串传递 |
| 时间 | 游戏发生时间、采集时间、有效期/状态版本；是否为跨时点读取或截断窗口 |
| 数据性质 | 游戏直接状态、观测事件、资源定义、统计派生、LLM 推断、Overlay 设定 |
| 来源与证据 | 游戏模块/采集器/MOD、版本、原始事件或快照引用、资源版本 |
| 角色视角 | 客观世界事实、玩家已显示信息、某 Sim 已知/亲历/被告知的信息；未知视角明确保留 |
| 可获得状态 | 已采集、不适用、未实例化、未支持、尚未观测、读取失败、过滤、截断；空值不混用 |
| 范围与粒度 | 全体还是部分集合、空间与时间范围、数量限制、数值单位/精度、是否降级模拟 |
| 推导说明 | 推导方法、证据集合和不确定性；仅对确有依据的估计附置信信息，不虚构“精确概率” |

采集 manifest 另外保存 DLC/MOD 清单、加载/覆盖信息、暂停/速度、游戏模式、当前玩家户/选中 Sim 和语言等运行框架信息。只有与当次 Overlay 有关的摘要需要进入模型输入。

如果 Overlay 的具体表现依赖屏幕位置，再增加可选的**客户端呈现数据**：镜头/视口、选中目标、UI 状态、物件到屏幕坐标的映射、同步截图或描述。它是额外采集通道；世界坐标无法独立说明目标当前是否在屏幕内，截图也不能代替角色的知识记录。

## 5. 避免类别交叉造成重复

分类用于确定数据的主要归属，关系通过引用连接。几个容易混淆的例子：

| 同一主题 | 状态/规则归属 | 发生/历史归属 | 角色知识归属 |
| --- | --- | --- | --- |
| 饥饿 | 当前值在 C03；食物效果配置在 C11 | 实际数值变化在 C09；相关经历检索在 C10 | 谁知道或感到什么，由 C08 的规则与证据表达 |
| 职业 | 当前职业、班次、进度在 C06 | 入职/升职事件在 C09；历史在 C10 | A 是否知道 B 的职业在 C08 |
| 关系 | 当前关系轨道/状态在 C04 | 确认关系事件在 C09；共同经历在 C10 | A 是否知道 B 已订婚在 C08 |
| 情境 | 约会实例、成员与进度在 C06 | 加入、离开、完成在 C09 | 哪些经历由角色感知在 C08 |
| 好恶 | 游戏原生人格偏好在 C02 | 经历推导的物件印象在 C10 | 对方是否知道这种偏好在 C08 |
| 交互 | 当前执行/队列在 C05；候选与规则在 C11 | 生命周期事件在 C09；历史使用记录在 C10 | 主动、接受、目睹分别关联主体和证据 |

例如“A 拥抱 B”可以有一个规范发生，关联 A 的主动视角、B 的接受视角和关系变化。分类中出现多次引用，不增加世界中的拥抱次数。

第三方 MOD 扩展也遵守同一原则：新增疾病归 C03，新增社团归 C04，新增物件资源归 C07；以 MOD 来源标注其身份。C12 主要保存生成内容与扩展系统的持续状态，避免成为所有 MOD 数据的混杂目录。

## 6. 不同 Overlay 对类别的需求

下表只是输入数据组合建议，不包含生成指令或 Prompt。

| Overlay 形式 | 主要 Context | 按需补充 |
| --- | --- | --- |
| 角色对白/聊天 | C01 场景、C02 画像、C03 状态、C04 关系、C05 活动、C08 知识、C09 近期事件、C12 对话连续性 | C06 情境目标、C10 相关共同经历 |
| 内心独白 | C02 画像、C03 状态、C05 活动、C06 目标、C08 本人已知、C09 近期事件 | C10 记忆、C11 实际决策证据、C12 已有独白 |
| 事件解说/场景描写 | C01 场景、C05 活动、C06 情境、C07 物件、C09 变化 | C04 关系背景、C10 历史、客户端呈现数据 |
| 物件记忆/印象展示 | C02 角色、C07 物件、C09 新事件、C10 历史印象 | C03 当时状态、C04/C06 关系与情境、C08 感知证据 |
| 情节延续/可选事件 | C04 关系、C06 目标、C07 资源、C09 当前进展、C10 历史、C11 条件、C12 进行中的情节 | C01 场景、C02/C03 角色画像与状态、C08 信息差 |

建议的数据供给节奏：常驻一份紧凑的场景与相关实体摘要；由事件增量更新；按角色、对象、情境检索历史、规则和详细属性。能否称为“足够”，最终由所选 Overlay 所需事实是否齐备来判断。

## 7. 示例：约会过程中吃牛排

以下为分类示例，不是对已有样本的重新断言，也不是 Prompt。

| 数据 | 归属与表达 |
| --- | --- |
| 两人在餐厅，游戏时间为傍晚 | C01：场所和时间 |
| A 的实际人格与烹饪技能 | C02：画像；B 是否知道这些属性另看 C08 |
| A 正在饥饿，有哪些 Buff、当前什么情绪 | C03：即时状态，不预设牛排是情绪的唯一原因 |
| A 与 B 当前关系尚未订婚 | C04：关系事实 |
| A 正在吃这份牛排，B 正在和 A 社交 | C05：各自交互，引用具体 Sim、物件与发生 ID |
| 二人属于同一次约会，目标进度如何 | C06：同一 Situation 实例及成员关系 |
| 牛排的实例、品质、剩余份数及归属 | C07：相关物件状态 |
| B 已知道 A 的职业，但是否目睹了某个细节未确认 | C08：已知信息和观测边界 |
| 吃完后 A 的饥饿数值实际增加 | C09：已观测变化及其可核验关联 |
| A 在过去的约会中对餐厅形成了某种印象 | C10：历史或派生印象，附证据和世界分支 |
| 此刻某个浪漫互动的实际 Test 已通过 | C11：当时条件成立；尚未执行，不能写成已发生 |
| Overlay 上轮已显示“下次再来”的对白 | C12：已展示内容；是否构成角色承诺、是否被 B 获知，需要对应记录 |
