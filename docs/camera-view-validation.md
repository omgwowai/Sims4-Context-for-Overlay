# 视锥查询验收

适用 MOD 0.11.0 / API、SDK 2.3.0 / schema 2。接口参数、覆盖和近似约定见[视锥查询](camera-view.md)，项目其他能力的证据见[验证摘要](validation.md)。

## 离线回归

在仓库根目录运行；游戏内代码还应使用 CPython 3.7 检查：

```powershell
python -B -X utf8 -m unittest discover -s tests -p test_camera_view.py -v
python -B -X utf8 -m unittest discover -s tests -q
```

`tests/test_camera_view.py` 覆盖六个视锥平面、相交半径、角度与宽高比、镜头方向、全量结果、区域与库存过滤、时效重置、覆盖缺口、线程／会话守卫、SDK 兼容性和不写历史。隐藏对象也必须占用原始管理器扫描预算；上限恰好等于条目数时可以完整返回，超过时必须报告 `scan_limit`。

## 实机复测步骤

使用与源码 manifest 匹配的构建，退出游戏后按[安装说明](install.md)部署，再加载普通生活模式地块。通过下游 MOD 的游戏线程回调调用 SDK，或启用[开发驱动](development.md#实机测试环境与请求)发送请求：

```json
{"operation": "api_camera_view", "params": {}}
```

驱动 `params` 原样转发公共 API 参数；响应外层 `ok/result` 是传输回执，视锥数据在 `result`。不要把驱动请求成功当成视锥扫描完整。

| 场景 | 需要保留并核对的证据 |
| --- | --- |
| 默认查询与空结果 | 相机与当前区域一致；结果、扫描量、coverage、参数来源和时效完整；相机不可用时报错 |
| FOV、宽高比、far 和 kinds | 暂停且保持镜头不变；宽视角包含窄视角集合，far 按前向深度筛选，kinds 只保留选定类型 |
| 地块外、楼层与库存 | 记录已知对象 ID 和位置；地块外与其他楼层可命中，隐藏／库存对象不入选；详情回查仍遵守活动地块范围 |
| 旋转、缩放和跟随 | 每次客户端操作后回读位置、目标、freshness 和命中集合；移动中跟随需连续回读，单次 follow=True 不能替代此项 |
| 暂停与正常速度 | 两种状态均可调用；记录历史接收序号，查询本身不应写入记录 |
| 读档与旅行 | 加载期间接口拒绝请求；跨区域相机不可复用；重置后没有新同步时 freshness 为 unknown |
| 测试收尾 | 记录并回读原暂停状态、镜头位置、目标及跟随模式；未确认的恢复项保持未确认 |

通过正常客户端镜头操作或 EA 发往客户端的相机指令触发同步，不直接向 `camera.update` 填入测试坐标。客户端可能调整请求的镜头位置，应以实际回读为依据。画面边缘精度需要在实际 viewport/FOV 下单独校准。

## 2026-09-24 实机样本

本节对应初次实现 `13ee0fb`，游戏 `1.126.73.1030`，MOD `0.11.0`，session `cda62f7fc0264cb28fccb6210b08e105`。运行时 `source_sha256` 与当时构建 manifest 一致；查询前后记录器接收序号均为 395，没有查询引起的历史写入。

| 同一暂停场景 | 命中数 | 完整调用耗时（单次样本） |
| --- | --- | --- |
| 默认 45°、16/9 | 78，其中地块外 50 | 16.7 ms |
| 垂直 FOV 120° | 192 | 29.0 ms |
| 仅 Sim | 1 | 1.8 ms |
| far=1 | 2 | 8.1 ms |

默认查询当时经 EA 预过滤枚举了 479 个非隐藏条目且 `coverage.complete=True`：338 个使用占地代理球、135 个使用寻路代理球、6 个使用坐标点。宽视角包含默认集合、距离上限缩小集合、类型筛选及大于 64 条的全量返回均经实测。耗时包括该次 API 返回数据的组装和复制，仅为此场景的样本，不是性能上限承诺。

**479 不是原始管理器总条目数。** 审查后已改为从原始条目计入预算，隐藏条目也计数；上表保持原始测量，不作为该修正之后的实机扫描量或性能结果。

通过原生 `FocusCamera` 发往客户端的旋转、拉远和跟随指令验证：客户端重新同步相机位置／目标点，查询分别得到 60、83、82 个命中，均完整；跟随步骤实测 `follow_mode=True`。客户端可以约束或调整请求的镜头位置，接口采用实际同步值。正常速度 `1` 下的查询也成功，随后已回读确认恢复暂停 `0`，镜头位置和目标点恢复为测试前值。没有保存存档。

时效限制也得到实测：只发跟随请求、没有新的相机同步时，`follow_mode` 仍保留上一条同步的值，`age_seconds` 持续增长。因此不能用“请求已发送”或 `freshness.status=observed` 证明客户端此刻的跟随开关状态；测试收尾的跟随开关回读未立即匹配原值，保留为未确认状态。默认 FOV 的画面边缘精度、移动中跟随的持续表现仍未做视觉校准，不以这些抽测宣称渲染器精确可见性。

本机证据位于忽略目录 `tmp/camera-view-20260924/`，包括 `report.json`、`checks.json`、各场景返回包、截图及实际发送到开发桥的脚本。为完成进档临时校准的 4K 菜单规则也保存在该目录，安装的 s4dev 规则已恢复原文件。

## 审查修正与验证边界

PR #12 审查发现预过滤枚举器使隐藏对象绕过扫描计数。新增回归先在原实现失败，再通过原始管理器惰性枚举修复；几何命中、名称读取及历史行为保持原契约。名称解析是否成功由 `entity.name` 内状态描述，与引用读取状态及 coverage 分别判断。

修复及文档整理后，2026-09-24 在 CPython 3.7 下完整回归 **401 项全部通过，无跳过**；其中视锥测试为 17 项。文档与 SDK 的分发链接清单检查通过，未生成 ZIP 分发包。

该预算修正尚未重复实机测试。默认 FOV 的画面边缘精度、移动中跟随的持续表现、此接口旅行后的实机同步，以及特殊镜头仍未完成验证。离线生命周期测试和上述抽测不能代替这些场景。原始本机证据不随源码或分发包附送。
