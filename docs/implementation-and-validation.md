# 首轮实现与验收

版本：v0.1。日期：2026-09-14。状态：实现计划，尚未执行。模块范围见[总体设计](modular-context-provider.md)，环境见[开发基线](reference-baseline.md)。

## 1. 首轮目标

在本地游戏中打通“指定目标当前状态 + 已观察历史 → 规范数据 → 可读表达 → 完整 JSON 输出”，并分别验证三个模块。

建议使用当前地块中的一个 Sim 和一张棋桌：读取身份、当前交互、地块与游戏时间，观察一段交互过程和实际可确认的结果，按目标查询历史并导出原始数据与中文描述。再用第二张同型号棋桌检查实例隔离。具体交互及终态入口需先核对源码与本地运行可用性。

事件记录从首轮纳入实现。旧 Experience 导入、长期记忆、任意时点状态重建、模型生成、复杂 UI 和游戏效果执行不作为前置条件。

## 2. 实现顺序

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| A：加载与最小读取 | 核对编译环境、构建包、安装目标和日志；增加一个最小调试入口，读取指定 Sim 与时间 | 游戏确认加载本项目，输出可定位的实体与时间；重复加载/换地块没有重复注册 |
| B：最小数据契约 | 用实际读取结果确定实体、时间、来源、事件、快照、可用性与版本；为模块准备最少样例 | 字段含义与范围可解释；示例不依赖旧 Experience 格式 |
| C：三个模块贯通 | 实现少量事件接入、查询组合、规则转换和文件导出 | 同一场景得到可追溯的原始事实与可读表达；独立关闭模块行为明确 |
| D：故障与范围验证 | 持久化、重复事件、实例隔离、未知结果及生命周期边界 | 声明范围内的验收通过，失败与未支持项都有记录 |

每个阶段只增加验收所需的辅助工具和测试。接口、词条与读取范围随真实数据核定，不能将本文示意能力标成已实现。

## 3. 共同验收标准

| 检查面 | 验收要求 |
| --- | --- |
| 来源与版本 | 每次结果可定位游戏版本、模块/规则版本及源码依据，记录本次 DLC/MOD 与场景范围 |
| 实体身份 | Sim、物件实例、资源定义不混淆；64 位身份经过 JSON/消费者后保持精确 |
| 一次发生 | 同一观测重复投递可去重；两次独立同名动作、两张同款物件不会误合并 |
| 状态与时间 | 当前值与直接查询相符；声明读取区间，历史时间和当前状态不混用 |
| 结果真实性 | 完成、取消、失败、未知/未闭合有证据；操作配置、取消请求不冒充实际后果 |
| 范围与缺失 | 未支持、读取错误、停用、空结果和截断明确；未完成必需项不能算成功 |
| 生命周期 | 换地块、对象卸载、重复注册及停止模块后行为可解释，不遗留重复订阅 |
| 存档与连续性 | 未验证跨运行连续性时明确隔离；读旧档后不把放弃的未来历史混入当前结果 |
| 持久化 | 已接收与已写入分开；失败不静默丢弃唯一记录；尾记录异常和重复重放可检测、处理 |
| 游戏行为 | 采集错误不改变原返回值、异常或游戏结果；对象访问时机正确，输出有界 |
| 语义表达 | 取消和未知不写成完成；缺词条保留原标识；文本可回到原始数据和规则版本 |
| 组合运行 | 仅事件记录、仅当前查询、仅离线语义化和三者全开均有明确输入/输出与能力状态 |

## 4. 验证方式与证据

纯数据逻辑使用新契约的合成样例验证身份、去重、时间、状态、规则和序列化。游戏接入使用受控操作与直接查询核对，不把同一个 Hook 的两份日志当作独立真值。

记录预期操作、实际结果、日志/输出位置、时间范围、失败项及采集缺口。对象和记录规模确定后测量查询耗时、读取区间、事件延迟、队列长度与文件增长，再制定预算；当前不虚构性能阈值。

静态定位、离线检查和游戏实测分开报告。没有启动游戏的检查不能写成游戏通过；旧原型的 13 项检查及旧参考项目的样本计数不代表新实现合格。

## 5. 首轮结束前需要核定

- 目标游戏的实际用户数据目录、脚本启用设置、编译解释器与加载路径。
- 采用的交互/通知入口、发送条件、实体身份、注销方式及已知版本边界。
- 第一版字段、结果状态、数据包与规则版本；所选内容类别和明确不覆盖范围。
- 持久化格式、输出目录、近期缓存和队列预算，以及写入确认语义。
- 模块关闭、原始/文本输出及失败回退的行为。
- 下一轮扩展依据：实际使用缺少哪些事实，哪些接口尚待核验。

首轮完成后再扩充 Buff、关系、物件状态等范围；新增能力继续按“需要什么事实—来自哪里—怎样验证—缺失怎样表达”登记。候选目录见[Context 分类](runtime-context-taxonomy.md)，后续玩法见[愿景资料](vision/README.md)。
